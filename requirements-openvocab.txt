# Zero-shot (open-vocabulary) component recognition.
#
# These backends recognise industrial components from natural-language
# descriptions instead of a trained class head, so they work with NO custom
# dataset — the prompts come from rtsp_backend/electrical/taxonomy.py. This is
# the fastest route to non-zero recognition before a bespoke model exists.
#
# Enable one on the AI Models page after installing:
#   openvocab_owlv2            google/owlv2-base-patch16-ensemble
#   openvocab_grounding_dino   IDEA-Research/grounding-dino-base
#   openvocab_florence2        microsoft/Florence-2-base  (needs einops+timm)
#
# NOTE: weights are fetched from the model hub on first use. On an air-gapped or
# restricted host, pre-download them elsewhere and point the backend's `model_id`
# param at a local directory. Without access the backend reports
# `weights_unavailable` with the exact reason — it never fabricates detections.
#
# CPU-only inference is slow (seconds to tens of seconds per image, depending on
# the model and how many taxonomy prompts are queried). Use them for uploaded
# still-image inspection, not for a live stream. Install the CUDA build of torch
# for a GPU host.
torch>=2.2
transformers>=4.45
Pillow>=10.0

# Florence-2 loads custom modelling code (trust_remote_code=True) that needs:
einops>=0.7
timm>=1.0

# NOTE: transformers may pull opencv-python as a transitive dep, which clobbers
# opencv-python-headless. Reinstall headless afterwards:
